# Deployment Plan: Myntra Digital Fitting Room

This document outlines the deployment strategy for the Digital Fitting Room, taking into account the Client-Server Split architecture, the GPU backend requirements, and the UI integration using the provided Stitch assets.

## 1. UI / Frontend Deployment
**Asset:** `stitch_realistic_frame_visualizer.zip`

The frontend UI generated by Stitch is contained within the provided zip file. Since this UI needs to be highly responsive and load quickly, it will be deployed via a Content Delivery Network (CDN).

- **Extraction & Build:** Extract the `stitch_realistic_frame_visualizer.zip` archive. If it contains a build step (e.g., `npm run build`), execute it in the CI/CD pipeline to generate the static assets.
- **Hosting:** Upload the compiled static assets (HTML, CSS, JS, Images) to cloud storage (e.g., AWS S3, Google Cloud Storage).
- **CDN Integration:** Serve the assets via a global CDN (e.g., AWS CloudFront, Cloudflare) to ensure low-latency delivery to mobile devices across all regions.
- **App Integration:** If this is being integrated into a native mobile app, these web assets will be loaded into an optimized WebView, or the component code will be ported directly into the native codebase.

## 2. API Gateway & Load Balancing
All client requests (Avatar generation, Photo uploads, Asset fetching) must pass through a robust API Gateway.

- **Service:** AWS API Gateway / Kong / Nginx.
- **Role:** Route traffic between the Asset Preprocessing Microservice and the GPU Worker Clusters.
- **Load Balancing:** Distribute incoming traffic evenly across backend instances to prevent any single node from being overwhelmed during high-traffic shopping events.

## 3. Backend & GPU Worker Clusters (The Heavy Lifters)
This is the core of the engine, responsible for rendering and computer vision tasks.

- **Infrastructure:** Kubernetes (EKS / GKE) with dedicated **GPU Node Pools** (e.g., NVIDIA T4 or A10g instances, optimized for inference).
- **Autoscaling (Crucial):** Configure Horizontal Pod Autoscaler (HPA) and Cluster Autoscaler. The cluster must aggressively scale up based on CPU/GPU utilization during traffic spikes (e.g., sales events) to prevent rendering latency.
- **Microservices Deployment:**
  - **Asset Preprocessing Service:** Deployed on standard CPU nodes for background removal and dimension standardization.
  - **Dual-Mode Engine (Mode A & B):** Deployed exclusively on GPU nodes to handle parametric 3D modeling and single-image silhouette warping.

## 4. Ephemeral Storage & Caching
Strict memory management is required to prevent client-side OOM crashes and to ensure fast asset delivery.

- **User-Facing Cache:** Deploy a fast in-memory datastore like **Redis** or **Memcached**. The Preprocessing Microservice will push standardized, low-polygon assets here so they can be instantly streamed to the client without async ingestion delays.
- **Vector Loading States:** The frontend (from the Stitch zip) handles the 3-second timeout fallback vector state locally while waiting for the cache/GPU.

## 5. Security & Ephemeral Container Sessions
Addressing Risk 4 (User Data Privacy Vulnerabilities).

- **Stateless Execution:** Configure the Kubernetes pods handling Mode B (Photo-Realistic AR) to run as **ephemeral, stateless containers**.
- **No Persistent Volumes:** Do not attach persistent storage (like EBS or EFS) to these specific pods.
- **Zero Retention Enforcement:** Implement a strict script within the container that forces a complete memory wipe (RAM purge) and terminates the session token immediately after the synthesized 2D/3D asset is returned to the client. No raw user photos should ever touch a database.

## 6. Rollout Strategy
- **Phase 1 (Alpha):** Internal dogfooding. Deploy to a staging environment and test with a limited set of pre-processed catalog items.
- **Phase 2 (Beta - A/B Testing):** Roll out the feature to 5% of live users on the Wishlist page. Monitor for client-side OOM crashes, API latency, and backend GPU scaling efficiency.
- **Phase 3 (General Availability):** Gradual rollout to 100% of users, scaling the GPU clusters proportionally.
